# Шпаргалка: чем что запускать

Все команды выполняются **из корня проекта**:

```
cd /Users/macbook/Desktop/projects/scara_robot
```

Питон везде `./.venv/bin/python` — системный `python3` не годится, нужные
библиотеки стоят только в окружении проекта.

Порт подставляется сам, если переходник в ноутбуке один. Иначе добавляйте
`--port /dev/cu.usbserial-A5069RR4`.

---

## Главное

### C30 Servo GUI — родная программа управления приводом

```bash
./gui/start_c30_servo.command
```

Ручной прогон, PID, автонастройка. Запускает самую свежую версию из `gui/`.
Двойной клик в Finder тоже работает.

> **Не держите её открытой одновременно с остальными скриптами.** Два ведущих
> на одной шине RS-485 накладывают кадры друг на друга — обмен рассыпается.

### Повтор позы руки — плечо и локоть на две оси

```bash
./.venv/bin/python tools/arm_control.py --confirm
```

Камера сверху смотрит на вытянутую руку. Плечо человека ведёт ось J1, локоть —
ось J2. Углы берутся из векторов между суставами, поэтому не зависят от того,
где вы стоите и как близко к камере.

Посмотреть без приводов:

```bash
./.venv/bin/python tools/arm_control.py --simulate
```

Сменить камеру (например на RealSense — он виден как обычная USB-камера):

```bash
./.venv/bin/python tools/arm_control.py --list-cameras
./.venv/bin/python tools/arm_control.py --confirm --camera 1
```

Если распознавание позы сверху скачет — цветные метки надёжнее:

```bash
./.venv/bin/python tools/arm_control.py --confirm --source markers
```

Запускается **на паузе**: сначала проверьте, что скелет лёг на руку правильно,
нажмите «ноль здесь», и только потом снимайте паузу.

Если рука в кадре, а робот реагирует редко — замерьте, где теряются кадры:

```bash
./.venv/bin/python tools/arm_control.py --diag
```

Двенадцать секунд подержите руку в кадре и подвигайте ей. Скрипт покажет
воронку по стадиям и скажет, что именно ослабить.

Приложение не даст снять паузу, пока не нажмёте «ноль здесь», и не стартует
на шумящей шине. Обойти проверку линии — `--skip-line-check`.

### Управление тремя осями двумя руками — основное приложение

```bash
./.venv/bin/python tools/scara_cv_control.py --confirm
```

Правая рука: X → мотор 1, Y → мотор 2. Левая рука: Y → мотор 3.
Окно с камерой, таблицей по осям, кнопками ПАУЗА / СТОП / «ноль здесь».

Посмотреть без приводов, только камеру и окно:

```bash
./.venv/bin/python tools/scara_cv_control.py --simulate
```

Если руки перепутались местами — `--swap-hands`.
Пределы осей правятся в `tools/scara_axes.json`.

### Слежение одной оси за рукой — простой вариант

```bash
./.venv/bin/python tools/hand_follow.py --source camera --confirm
```

Одна ось, слева 0°, справа 360°. Мышью вместо камеры — `--source mouse`.
Без железа — `--simulate`.

### Звук при срабатывании концевика

```bash
./.venv/bin/python tools/switch_sound.py --random
```

Слушает плату и проигрывает звук на каждое замыкание. Варианты:

```bash
./.venv/bin/python tools/switch_sound.py --list           что доступно
./.venv/bin/python tools/switch_sound.py --sound Sosumi
./.venv/bin/python tools/switch_sound.py --say "оба-на" --voice Bubbles
```

Монитор порта в Arduino IDE при этом должен быть закрыт — порт держит
только одна программа.

### Голосовые команды

Работают сами при запуске, офлайн. Три слова:

| Скажите | Что делает |
|---|---|
| **стоп** | останавливает оси (то же, что кнопка СТОП) |
| **старт** | снимает паузу |
| **линия** | принимает текущую позу за середину |
| **положение** | первый раз — запомнить исходное, дальше — вернуться в него |

Понимает и синонимы: «стой», «хватит», «пуск», «поехали», «линию». Выключить — `--no-voice`. Если микрофонов несколько,
выбрать: `--audio-device 1`.

### Проверить камеру RealSense отдельно

```bash
sudo .venv-rs/bin/python tools/rs_check.py
```

Открывает камеру тем же кодом, что и основная программа, и печатает
каждый шаг. Пять секунд вместо запуска всего подряд.

### Проверить, что ничего не сломано

```bash
./.venv/bin/python tools/selfcheck.py
```

Доктесты, все точки входа и контур слежения на симуляторе привода.
Железо не нужно. Запускать после любой правки кода.

## Диагностика (начинать отсюда, если что-то не работает)

### Проверить, чистая ли шина

```bash
./.venv/bin/python tools/bus_health.py
```

Слушает линию, ничего не передавая. Должно прийти **0 байт**. Если байты
идут — обмен будет зависать, и это надо чинить до всего остального.

### Найти переходник USB-RS485

```bash
./.venv/bin/python examples/ports.py
```

### Найти приводы на шине

```bash
./.venv/bin/python examples/scan_bus.py /dev/cu.usbserial-A5069RR4 --baud 19200 --parity E --ids 1-8
```

Ничего не пишет, только читает. Параметры связи неизвестны — уберите
`--baud` и `--parity`, тогда переберёт все варианты.

### Проверить, куда крутит привод

```bash
./.venv/bin/python tools/check_direction.py --confirm
```

Двигает вал по 2 с в каждую сторону и говорит, согласованы ли знаки команды,
энкодера и сообщаемой скорости. **Вал крутится — ось разгрузить.**

## Регистры

### Прочитать

```bash
./.venv/bin/python examples/mb.py read P-004
./.venv/bin/python examples/mb.py read 0x1010
./.venv/bin/python examples/mb.py read P-028 --count 3
```

Адрес понимается тремя способами: `P-004`, `40077` (нотация 4xxxx) и сырой
`0x1010`.

### Записать — всегда со сверкой

```bash
./.venv/bin/python examples/mb.py write P-076 100 --verify
```

`--verify` обязателен: без нужного пароля (`P-000`, по умолчанию 315) запись
проходит молча, а значение не меняется.

### Смотреть регистр в реальном времени

```bash
./.venv/bin/python examples/mb.py watch 0x101F --count 2
```

### Другой привод на шине

Ко всем командам добавляется `--id`:

```bash
./.venv/bin/python examples/mb.py read P-004 --id 2
```

## Если камера не открывается

Доступ выдаётся приложению, из которого запущен python, и подхватывается
**только новым процессом**. Порядок: разрешить в диалоге или в Системные
настройки → Конфиденциальность и безопасность → Камера, затем **перезапустить
Терминал целиком**, и только потом запускать скрипт. Перезапуск самого скрипта
не помогает.

## Снимок версии

Копия дерева в `../scara_robot_backups/<дата>` плюс тег в гите:

    tools/backup.sh "что в этой версии"

Вернуться к снимку: `git checkout версия-<дата>` (если тег ставился) или
просто скопировать папку обратно.

## Проверки перед выдачей

    ./.venv/bin/python tools/selfcheck.py           # окно, контур, доктесты
    ./.venv-rs/bin/python tools/voice_check.py      # голос на записях

## Версии: как смотреть, откатываться и возвращаться

Каждая заметная версия сохраняется дважды, и это разные вещи.

**Тег в гите** — точка, к которой можно вернуться целиком.

    git tag                          # список версий, новые внизу
    git log --oneline -10            # что менялось, коротко

Посмотреть старую версию, ничего не ломая:

    git checkout версия-20260907_184941

Вы окажетесь «в стороне от ветки» — это нормально, файлы будут те.
Запускать оттуда можно как обычно. Вернуться к последней версии:

    git checkout master

Если в старой версии что-то захотелось оставить — не копируйте руками,
скажите мне, какую версию и что именно.

**Копия папкой** — на случай, когда гита мало: там лежит и то, что не
зафиксировано, включая настройки, которых в гите нет.

    ls ../scara_robot_backups                     # все снимки
    cat ../scara_robot_backups/*/ЧТО_ЭТО.txt      # чем каждый был

Запустить прямо из снимка, не трогая рабочую папку:

    cd ../scara_robot_backups/20260907_184941
    ../../scara_robot/.venv/bin/python tools/arm_control.py --simulate

Откатить рабочую папку к снимку целиком:

    rsync -a --delete ../scara_robot_backups/20260907_184941/tools/ tools/

Новый снимок делается так (я делаю его сам перед каждой правкой):

    tools/backup.sh "чем эта версия отличается"

## Ракурс камеры и модель распознавания

Записать кусок со своей камеры и померить на нём модели:

    ./record_realsense.command --секунд 10
    ./.venv/bin/python tools/pose_compare.py clips/клип_*.npz --повороты

Запуск с выбранной моделью:

    ./run_realsense.command --pose-model heavy
    ./run_realsense.command --pose-model heavy --rotate 90

## Помехи на шине

    ./run_realsense.command --timeout 0.1 --retries 3

Доля сбойных обходов видна в диагностике рядом с «шина ... мс».

## Своя модель позы под камеру сверху

Порядок ровно такой, шаги через один не пропускать.

**1. Снять запись со своего места** (10 секунд достаточно):

    ./record_realsense.command --секунд 10

**2. Померить, хватит ли готовых моделей.** Может оказаться, что heavy
с поворотом закрывает вопрос и обучать ничего не надо:

    ./.venv/bin/python tools/pose_compare.py clips/клип_*.npz --повороты

Если «рука видна» вышла выше 90% и дрожь угла мала — берите эту модель
и на этом всё:

    ./run_realsense.command --pose-model heavy --rotate 90

**3. Если не хватило — размечать.** Нужна запись подлиннее, минуты три,
и с разными положениями руки:

    ./.venv/bin/python tools/label_clip.py clips/клип_*.npz --шаг 5

Кадры сначала размечает тяжёлая MediaPipe; там, где она справилась,
достаточно нажать `a` и `n`. Где не справилась — три щелчка мышью:
плечо, локоть, кисть.

**4. Обучить:**

    pip install ultralytics
    yolo pose train data=dataset/data.yaml model=yolo11n-pose.pt epochs=100 imgsz=640
