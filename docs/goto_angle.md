# Выход в заданный угол

«Задал угол — приехал». Настраивать нечего.

```bash
.venv/bin/python examples/goto_angle.py 90
.venv/bin/python examples/goto_angle.py 90 180 270 0     # по очереди
.venv/bin/python examples/goto_angle.py 90 --simulate    # без железа
```

Настройки связи и энкодера берутся из `gui/c30_servo_settings.json` — того же
файла, что использует GUI, так что программный ноль и counts/оборот общие.

## Почему не PID

У PID поверх Modbus три беды, которые коэффициентами не лечатся:

1. **Скорость задаётся целым числом об/мин.** Медленнее 1 об/мин (6 град/с)
   привод не умеет. У самой цели это значит, что за один цикл обмена (~60 мс)
   вал проскакивает ~0.4° — сравнимо с желаемой точностью.
2. **Мёртвое время.** Между «прочитал положение» и «привод отреагировал» —
   десятки миллисекунд. Для регулятора это чистая задержка: она съедает запас
   устойчивости и раскачивает контур именно у цели.
3. **Момент трогания.** Стронуться с места тяжелее, чем ехать. У цели
   регулятор выдаёт малый выход, вал стоит, ошибка не убывает.

Отсюда знакомая картина: подъехал, проскочил, вернулся, проскочил.

## Как работает этот алгоритм

Приближение уступами и обязательная проверка **после остановки**:

| Ошибка | Что делает |
|---|---|
| больше 20° | едет на максимальной скорости |
| 3…20° | скорость пропорционально ошибке, снижается на ходу |
| меньше 3° | короткие толчки: тронулся, чуть проехал, встал |
| внутри допуска | стоп, пауза, **перечитать положение** |

Ключевое — последняя строка. Позиция засчитывается только после остановки, а
не в момент пролёта через неё. Вне допуска после успокоения — ещё заход.
Алгоритм не угадывает динамику привода, он её измеряет, поэтому подбирать
ничего не нужно.

## Проверено на симуляторе

`tests/test_goto.py` моделирует то, что мешает на железе: целое задание
скорости, разгон первого порядка, время транзакции Modbus и задержку чтения
положения. Время виртуальное — минуты движения проходят за миллисекунды.

```bash
.venv/bin/python -m unittest discover -s tests -v
```

60 прогонов со случайных углов в случайные: **все доезжают**, худшая ошибка
1.00° при допуске 1°, самый долгий выход 4.2 с. Отдельно проверено: путь через
ноль выбирается короткий (359° → 1° это +2°, а не −358°), шум датчика 0.2° не
мешает, вдвое медленная связь не мешает, а заклинивший вал даёт внятную
ошибку, а не зависание.

## Про допуск

Разумный минимум — **около 1°**. Ниже мешает физика, а не программа: на
минимальной скорости 1 об/мин вал проходит 6 град/с, и за время остановки
(десятки миллисекунд) успевает уйти на несколько десятых градуса.

Нужна точность лучше — это уже импульсный тракт, где позицию считает сам
привод: [pulse_positioning.md](pulse_positioning.md).

## Из своего скрипта

```python
from scara_drive import (
    C30AngleIO, DriveConfig, GotoController, GotoProfile, SerialConfig, ServoDrive,
)

cfg = DriveConfig(serial=SerialConfig(
    port="/dev/cu.usbserial-A5069RR4", baudrate=19200, parity="E", device_id=1,
))

drive = ServoDrive(cfg)
drive.connect()
try:
    io = C30AngleIO(drive, counts_per_rev=131072)
    io.enable()
    controller = GotoController(io, GotoProfile(tolerance_deg=1.0, max_rpm=20))

    for angle in (90, 180, 270, 0):
        print(controller.goto(angle))
finally:
    io.hold()
    drive.close()
```

## Безопасность

`goto()` останавливает привод в `finally` — и при успехе, и при исключении, и
по Ctrl-C. Но это программный останов: аппаратный аварийный и концевики должны
работать независимо от ноутбука.
