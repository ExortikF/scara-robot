# Почему углы по Modbus этому приводу не задать

Разбор идеи «с компа по Modbus RTU подаём углы, привод сам едет и отвечает,
что встал». На этом приводе она не собирается. Ниже — почему, с ссылками на
страницы руководства, и что вместо неё.

## Параметры позиционного режима — это настройки, а не команда

Таблица 4.2 (стр. 37) называется «Key parameter settings for position control
mode». Ключевое слово — **settings**. Разберём построчно:

| Параметр | Что делает | Это команда положения? |
|---|---|---|
| `P-004 = 0` | включает позиционный режим | нет, только режим |
| `P-028`/`P-029`/`P-030` | электронный редуктор — во сколько раз умножается **входящий импульс** | нет, масштаб |
| `P-035` | формат импульсов на входе (импульс+направление / вперёд-назад / A-B) | нет, формат входа |
| `P-036` | инверсия направления счёта импульсов | нет |
| `P-005`, `P-006` | коэффициенты контура скорости | нет, жёсткость |
| `P-009` | коэффициент контура положения | нет, жёсткость |
| `P-007` | фильтр момента | нет, подавление вибрации |

Все они описывают, **как привод обработает импульсы, которые придут на PULS±/SIGN±**.
Ни один не содержит целевую позицию. Регистра «ехать в точку N» в руководстве нет.

`P-005`, `P-006`, `P-009` особенно легко принять за управление, но это
настройки жёсткости: «увеличивать по 10, пока не начнётся вибрация»
(стр. 37-38). Их выставляют один раз при наладке.

## Доказательство от списка входов

Самое надёжное подтверждение — список функций DI, стр. 76. Смотреть надо на
то, чего в нём **нет**.

Что есть:

* `SP1`, `SP2`, `SP3` — выбор внутренней **скорости** (три бита = до 8 пресетов);
* `TRQ1`, `TRQ2` — выбор внутреннего **момента**;
* `GEAR1`, `GEAR2` — выбор электронного редуктора;
* `ORN` — возврат в ноль.

Чего нет: `POS1`/`POS2` (выбор внутренней позиции) и `CTRG` (триггер пуска
отрезка). У приводов с PR-режимом — тем самым «движением по положениям» —
эти входы есть всегда, иначе таблицу точек нечем запускать.

Вывод: внутренние пресеты у привода есть по скорости и моменту, но **не по
положению**. Задать позицию числом ему просто нечем — ни по Modbus, ни с
клеммника.

## Про обратную связь «встал»

Признак существует: `DO` функция №5 `COIN` — *Positioning complete* (стр. 77).
Есть и №10 `NEAR` — подход к позиции.

Но это **функция дискретного выхода**, то есть физический контакт на разъёме.
Читается ли состояние DO через Modbus — руководство не говорит; раздел 3.3
«Status monitoring» описывает панель, а не адреса регистров. Так что план
«опрашивать готовность по Modbus» — гипотеза, требующая проверки на железе, а
не факт.

## Отдельная мина: пароль

`P-000` — operating password, по умолчанию `315`. А `P-001`, `P-002`, `P-099`
требуют `385` или `316`, иначе **правка не применяется** (стр. 77).

Опасность в том, как это выглядит со стороны Python: Modbus-запись проходит
успешно, привод отвечает «ок», а значение не меняется. Молчаливый отказ.
После каждой записи параметра читайте его обратно и сверяйте.

## Второй вариант: Ethernet

У этого привода Ethernet нет. По правилу обозначения модели (стр. 134,
`C30-L20A-RABN`) поле «Communication type» принимает ровно два значения:

* `G` — связи нет;
* `R` — изолированный **RS-485**.

Всё. Никакого Ethernet, EtherCAT или PROFINET в этой серии. Связка «Python +
Ethernet + привод» напрямую не существует — между ними в любом случае нужна
коробка, которая превращает пакеты в импульсы или в RS-485.

## Что остаётся, по возрастанию мороки

| Цель | Как | Железо |
|---|---|---|
| Просто убедиться, что мотор крутится | JOG с панели привода (Fn-20 / JOG trial run, стр. 35) | ничего |
| Крутить из Python | Modbus RTU, скоростной режим (`P-004 = 1`) | USB-RS485 свисток |
| Ехать в позицию из Python | импульсы STEP/DIR | плата-генератор импульсов |
| Ехать в позицию по Ethernet | Ethernet-плата, выдающая STEP/DIR | ESP32 с Ethernet / ПЛК |

Строка 2 — это ровно то, что уже реализовано в
[../src/scara_drive/driver.py](../src/scara_drive/driver.py): крутит, но не
позиционирует. Строка 3 — [realtime_pulses.md](realtime_pulses.md).

## Если очень хочется позиционировать именно по Modbus

Тогда контур положения придётся закрывать самому: читать текущее положение,
считать ошибку, писать скорость, повторять. Это `ServoDrive.move_to()`.
Ограничения честные: цикл обмена по RS-485 — десятки миллисекунд, поэтому
годится для медленной доводки, но не для движения робота. И для этого нужен
адрес регистра текущего положения, которого в снятом дампе нет.

Правильнее не воевать с приводом, а дать ему то, что он ждёт — импульсы.
